# 광고 신청 운영자 체크리스트

이 문서는 다섯 정보 사이트의 운영자가 광고 신청·상태 확인·반려 대응을
기록하기 위한 비공개 작업 문서다. 영상 경험담과 공식 도움말을 구분하며,
어느 항목도 승인 보장이나 자동 실행 규칙으로 취급하지 않는다.

## 1. 배포 전 실제 확인

1. 각 도메인의 루트와 `www`가 HTTPS로 열리는지 확인한다.
2. 도메인별 `/robots.txt`, `/sitemap.xml`, `/ads.txt`가 실제 200 응답을
   반환하는지 확인한다.
3. 페이지 HTML의 `<head>`에 현재 계정용 AdSense 코드가 들어 있는지
   확인한다. 현재 계정 코드가 바뀌면 코드와 `ads.txt`를 함께 다시
   확인한다.
4. 홈·목록·대표 상세 글·가이드·소개·출처·문의·개인정보·이용약관이
   모바일과 데스크톱에서 정상적으로 열리고 내부 링크가 깨지지 않는지
   확인한다.
5. 각 콘텐츠가 다른 독자 질문을 해결하는지, 원문 링크와 마지막 검토일이
   있는지, 빈 카테고리·데모 문구·반복 문장이 없는지 확인한다.

## 2. 계정 화면에서만 확인할 일

다음 항목은 코드가 대신 실행할 수 없다. 신청 직전에 현재 AdSense 화면과
공식 도움말을 대조해 운영자가 직접 기록한다.

- 사이트 URL을 입력할 때 현재 화면이 요구하는 형식과 국가 설정
- 소유권, 사이트 연결, 검토 요청 가능 여부, 보류·주의·검토 상태의 실제 문구
- 계정에 표시되는 계정 코드와 `ads.txt` 안내 행
- 장기 무응답일 때 개인 설정의 연락처와 전화번호 국제 형식
- 광고 설정, PIN, 결제 수단, 자동 광고 또는 광고 단위 배치

동영상에서 보인 화면의 색·버튼·상태명은 과거 UI일 수 있다. 현재 계정의
상세 메시지가 영상이나 메모보다 우선한다.

## 3. 콘텐츠 공개와 안정화 선택지

원본 영상에는 서로 다른 공개·신청 방법이 함께 나온다. 이 프로젝트는 그
차이를 지우지 않고, 실제 운영 기록에 선택 이유를 남긴다.

- `안정화`: 마지막 핵심 편집 글을 공개한 뒤 일정 기간 화면·링크·원문을
  다시 확인하고 신청한다. 심사 중에는 사실형 항목의 오류 정정 외 새 편집
  글을 보류하는 방식이다.
- `운영형`: 공식 원문 변경과 독자가 실제로 찾는 문제 해결 글을 계속
  검토·공개하는 방식이다. 단, 일정만 흉내 내기 위한 예약 발행이나 무근거
  자동 게시를 하지 않는다.

글 개수, 이미지 개수, 3~4시간 간격, 48시간 대기 같은 수치는 영상 속
운영 경험일 뿐 Google의 공개 최소 요건이 아니다. 현재 품질 검사와 실제
사이트 상태가 더 중요하다.

## 4. 반려·무응답 기록

반려가 발생하면 기존 콘텐츠를 일괄 삭제하지 않는다. 아래 순서로 실제
변경 근거를 남긴다.

1. AdSense 화면과 이메일의 원문 메시지, 날짜, 해당 도메인을 기록한다.
2. 영향을 받는 홈·목록·상세·정책·기술 경로를 점검한다.
3. 반복적이거나 출처가 약한 문장을 고치고, 실제 독자 질문을 해결하는
   독립 글만 추가한다.
4. 바뀐 URL, 원문 출처, 테스트 결과를 함께 기록한다.
5. 현재 AdSense 화면에서 요구하는 조치가 모두 끝난 뒤에만 재검토 요청을
   고려한다.

새 글 1~2개, 사이트 재등록, 계정 변경, 가족 계정, 다수 사이트 동시 신청은
영상에서 제시된 경험담이다. 이 프로젝트는 이를 자동으로 실행하거나
승인 해결책으로 표시하지 않는다.

## 5. 승인 후에도 남는 점검

광고가 표시되기 시작해도 운영이 끝나는 것은 아니다. 현재 AdSense 화면에서
광고 설정·표시 상태를 확인하고, 같은 위치에 서로 다른 광고 코드를 겹치지
않게 관리한다. 외부 유입, 제휴, 커뮤니티, SNS는 별도 운영 판단으로 남기며
개인정보·저작권·광고 고지 의무를 개별적으로 확인한다.

## 6. 기술 구조와 이 문서의 한계

현재 본체는 Next.js + Vercel 방식이다. WordPress, Cloudways,
All-in-One Migration, 고유주소 저장, 관리자 계정, 호스팅 이전 절차는
원본 영상에 포함된 다른 플랫폼의 방법이므로 현 코드에 자동 적용하지
않는다. 이전을 실제로 결정할 때는 그 시점의 호스팅·보안·DNS 안내를
별도로 검토한다.
